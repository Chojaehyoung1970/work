# 제작·검증 기록: 학습 자료 및 링크 정리 페이지

## 두 AI 비교
- AI A (서비스·모델 이름): Claude (claude.ai, Claude Sonnet 5.5) → `학습자료및링크정리_클로드.html`
- AI B (서비스·모델 이름): Gemini (모델명은 직접 기입) → `학습자료및링크정리_제미나이.html`
- 동일한 기획서와 함께 전달한 요청: 기획서(`기획서.txt`)를 첨부하고 "이 기획서대로 HTML 파일 하나를 만들어 줘. CSS와 JavaScript까지 모두 이 파일 하나에 넣고, 다른 파일이나 로그인 없이 브라우저에서 바로 열리게 해 줘. 화면 문구는 한국어로 쓰고, 기획서에 없는 기능은 넣지 마"
  - (Gemini에 보낸 문장이 이와 다르면 실제로 보낸 문장으로 고쳐 주세요.)

테스트 방법: 두 파일을 같은 순서로 헤드리스 Chromium(데스크톱 1280×800, 모바일 375×740)에서 실행해 비교했습니다.

| 테스트 내용 | AI A (Claude) | AI B (Gemini) |
| --- | --- | --- |
| 처음 열었을 때 샘플 5개, 기본 카테고리 5개 | 통과 (링크 없는 자료 1개 포함) | 통과 (링크 없는 자료 1개 포함) |
| 자료 추가 → 제목·URL이 목록에 그대로 표시 | 통과 (맨 앞에 표시, 링크 주소 일치) | 통과 (맨 앞에 표시, 링크 주소 일치) |
| 수정(기존 값 채움·반영), 삭제(확인 창), 새로고침 후 유지 | 통과 | 통과 |
| 새 카테고리 추가 → 선택 목록에 나타남 | 통과 (추가 즉시 선택됨, 이미 있는 이름이면 기존 항목을 선택하고 별도 안내는 없음) | 통과 (추가·중복 때 알림창이 뜸) |
| 표 ↔ 카드 전환, 정렬(최근/이름), 다크 모드 | 통과 (표 6열: 제목·카테고리·설명·태그·추가일·관리) | 통과 (표 5열: 카테고리·제목·설명·태그·관리) |
| 이름순 정렬 결과 | 한글 → 영문 순 (`localeCompare('ko')`로 고정) | 영문 → 한글 순 (브라우저 기본 언어 설정에 따라 달라질 수 있음) |
| 공백만 입력한 제목 | 저장되지 않고 폼이 열려 있음 | **제목이 빈 카드가 저장됨** |
| `https://` 없이 입력한 주소 (`example.org/path`) | 자동으로 `https://`를 붙여 저장 | 저장되지 않고 폼이 열려 있음 (브라우저 `type=url` 검사) |
| `<img onerror=…>` 같은 태그를 제목에 입력 | 글자 그대로 표시, 실행 안 됨 | **스크립트가 실행되고** 설명에 쓴 `<b>`도 서식으로 렌더링됨 (`innerHTML` 사용) |
| 자료를 전부 삭제한 뒤 새로고침 | 빈 목록 유지 | 샘플 5개가 다시 나타남 |
| 입력 폼 닫기 (Esc 키) | 닫힘 | 안 닫힘 (취소 버튼만 가능) |
| 375px 폭 화면 | 가로 넘침 없음, 상단 버튼이 줄바꿈되어 정돈됨 | 가로 넘침은 없지만 상단 버튼이 좁아져 "라이트 모드"·"+ 자료 추가"가 글자 단위로 세로로 꺾임 |
| 자바스크립트 오류 | 없음 | 없음 |

- 선택한 결과물과 근거: **Claude 파일 (`학습자료및링크정리_클로드.html`)** 을 선택했습니다. 기획서의 완료 기준 항목은 두 파일이 모두 충족했습니다. 차이는 예외 상황에서 났습니다. Claude 파일은 빈 제목을 막고, 입력한 글자를 실행하지 않고 그대로 보여 주며, 폼이 Esc로 닫히고, 모바일 상단 바가 깨지지 않습니다. Gemini 파일은 이 네 가지에서 문제가 있었고, 자료를 전부 지워도 새로고침하면 샘플이 되살아났습니다. 다만 Gemini 파일의 샘플 자료(React 공식 문서, Velog 등)가 학습용으로는 더 구체적입니다.
